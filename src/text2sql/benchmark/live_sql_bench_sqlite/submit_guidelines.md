LiveSQLBench Submission Guidelines:

Thank you for your interest in LiveSQLBench. We appreciate your efforts in advancing research in this area. To ensure accurate and transparent evaluation, please refer to the following submission guidelines.

I. Please structure the email title as follows:
`[livesqlbench-{split}][Team Name][Method Name]`

`split`: Specify the dataset split (e.g., `base-lite`, `base-full-v1`, `large-v1``) for which you are submitting results.
`Team Name`:  The official name of your research team or organization.
`Method Name`: A concise and descriptive name for your proposed method (e.g., `SQL-Agent`).

Example: `[livesqlbench-base-lite][HKU][SQL-Agent]`

II. Submission Contents:

Please include the following information in your submission. Feel free to contact bird.bench25@gmail.com if you have any questions or feedback!

1.  Prediction file: This file should contain your model's predicted SQL queries and accompanying reasoning traces for each example in the specified split. We recommend the following format:

Format: We recommend JSONL file.
Each entry should correspond to a single example and include the following fields:
`instance_id`: the id of instances in the original set.
`pred_sqls`: The predicted SQL query. (A list of String)
`prompt_flow` (Option 1. for prompt-based/workflow methods): A list of dictionaries detailing the model prompts and responses used at each step of the process. For non-agent methods, this may be the primary trace. Each dictionary should contain:
● `model`: The name or identifier of the model/API used (e.g., `"gpt-4o"`, `"claude-3.5-sonnet"`). For open-source models, please provide a direct link (e.g., `meta-llama/Llama-3.1-8B`) to the model repository on Hugging Face Hub or ModelScope. If you are using a proprietary model, please use `"my_model"` as the identifier.
● `prompt`: The exact prompt string used for the corresponding step.
● `response`: The raw response of each step
`agent_trajectory` (Option 2. for agent-based methods): A chronological list of actual agent events/steps. Each event/step should preserve enough information for us to audit how the final SQL was produced, e.g. tool call and observation. Be flexible of the Json structure for your agent.
`cost`: Please provide the cost in USD for each task, based on the API pricing from the model provider or OpenRouter. This cost is used to indicate the efficiency of your method.

2.  Model Access: If you are submitting results generated by a custom or proprietary model (identified by `"my_model"` in the `prompt_flow`), we kindly request temporary access to your model for validation purposes. This will allow us to independently verify your results and ensure fairness. Please specify the duration of access you are willing to provide and any necessary API keys or credentials. We guarantee that all model access will be used solely for validation and will be terminated promptly upon completion. The model and associated data will not be distributed in any format.

3.  Other Supporting Information:

(Optional) Team Logo: A PNG format logo of your team or organization.

(Optional) Future Plans: A brief description of your future plans for improving your method or contributing to the LiveSQLBench benchmark.

(Optional) Contact Information: A project website, repository link, or contact email that can be publicly displayed on the leaderboard.

II. Validation Submission Mode:
In addition to the submission guidelines above, we also support a Validation Mode. In this mode, you may provide us with your source code and model instead of prediction files. Our team will run your code & model locally and evaluate the results. We recommend running each submission at least three times; we will report the best result among them. You may submit your coding files to bird.bench25@gmail.com, referring to BIRD-SQL 2023: BIRD-Test Submission Guidelines:

Successfully validated submissions will be added to the LiveSQLBench leaderboard with a corresponding verified badge to prove our team has carefully checked.

III. Submission Procedure:
Please send your submission, including all required files and descriptions, to bird.bench25@gmail.com.

IV. Submission Privacy:

We promise that all submitted files, methods, and models will remain confidential. We will use them solely for the purpose of validating your results. We will not distribute your data, code, or models in any form. Our validation process aims to provide objective benchmarks for the community.

Contact Information (Optional but Recommended):
To facilitate academic collaboration, we encourage submitting teams to include a project link, homepage, or contact email that can be displayed on the leaderboard. This allows interested researchers to directly reach out to the corresponding teams for further discussion or potential collaboration.
